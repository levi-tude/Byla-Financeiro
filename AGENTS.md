## Learned User Preferences

- Communicate in Portuguese; when the user says "calma" or is lost, pause and explain simply before continuing work.
- Default feature cycle: discuss and model the idea, write an implementation prompt, wait for explicit approval, then implement strictly to that prompt; when the user asks to write a prompt and apply it immediately, or authorizes continuous/uninterrupted execution for a scoped task, proceed without further approval gates; for risky UX/layout fixes after a bad result, write a prompt-engineering analysis (before/problem/alternatives) before implementing again.
- Prefer short, plain end summaries of what changed and why; avoid dumping intermediate process detail unless asked.
- Product copy, reports, and UX should target Secretária, Admin, and gestão — not developers; hide planilha-row internals (linha, ordem, etc.); explain features to staff in short, simple Portuguese; in Controle de caixa label the planilha-migrated mode as Planilha (not Oficial).
- Secretária owns Fluxo de caixa (alunos/modalidades/pagamentos); Admin/Administrativo owns Controle de caixa.
- Keep the public GitHub repo as portfolio; remove sensitive docs from GitHub (keep local or delete) rather than taking the repo private; do not force-push or change visibility without explicit approval; portfolio screenshots must use fictional data only (never real PII or production finances).
- Publish to the site in waves via skill `.cursor/skills/subir-alteracoes-site` (rule `publicar-site-sem-pii`); never put client PII in Git — real names/rules and operational Validação edits live in Supabase (not Git publish waves); tests use fictional fixtures; no force-push to `main` without explicit approval.
- Do not treat Docker as the everyday runtime for the main app; temporary local/demo Docker is acceptable only when needed.
- Manual validation links, crédito-recorrente bank↔aluno links, and person/category classifications must survive remigrations and carry across months (sticky); the user should not re-link the same payment or classification every month.
- When the user asks to validate in the browser, prefer starting (or confirming) the local frontend/backend stack rather than only describing how to run it.
- In-app page UI state (filters, search, open aluno, view mode) should survive route changes via sessionStorage until the browser tab/site is closed — not reset on every navigation.
- Desktop sidebar uses position sticky; do not put overflow-x-hidden (or any overflow ≠ visible) on ancestors that wrap both sidebar and main — clip horizontal overflow only on main/outlet.
